# Rule · a migration is also an audit

The rules for this repo were first written as Cursor `.mdc` files. On 2026-06-23 they were moved into
Claude Code's path-gated `.claude/rules/`. The commit message records what the move found:

```text
Import two project-agnostic process rules from stt-faster
(plan-hygiene, rule-authoring) and adopt the project's
.cursor/rules/*.mdc as path-gated .claude/rules/*.md:
linting, logging, langchain, testing, docker-safety,
python-imports-and-deps.

(one paragraph omitted: the CLAUDE.md it added)

Fix stale cursor rules against current uv-native setup:
- rewrite python-imports-and-deps.mdc (uv source of truth,
  [dependency-groups], autogenerated requirements.txt, fixed
  DEVELOPMENT.md path)
- delete uv-sandbox.mdc (tools/uv_sandbox absent; root pyproject
  is uv-native)
```

The Cursor rule it deleted still told the agent to do the opposite of what the repo did:

```md
- Purpose: Use pip for app/CI; use `tools/uv_sandbox/` only to resolve complex pins.
  (two lines omitted)
  - No `[tool.uv.*]` in root `pyproject.toml`; UV config only in `tools/uv_sandbox/pyproject.toml`.
```

Each migrated rule got a date stamp in its frontmatter:

```yaml
---
paths:
  - "tests/**/*.py"
  - "**/*_test.py"
last_verified: 2026-06-23
---
```

## What didn't work

Nothing checked the old rules against the code. The repo had moved to `uv`, but the rule still named a
`tools/uv_sandbox/` directory that was gone. That only came to light because moving each rule meant
reading it again.

## Where it came from

The **public** repo `KristjanHS/kri-local-rag`: the commit of 2026-06-23, its deleted
`.cursor/rules/uv-sandbox.mdc` and its new `.claude/rules/testing.md`. A reader can check all three.
