## The problem

The files carry **no timestamps**. Filesystem mtimes are all the export date (Sep 2025 / Sep 2026), not the
chat date. The `.md` bodies have no frontmatter and no per-turn times — a thread is just alternating
`**You:**` / `**ChatGPT:**` blocks. Filenames are `<ChatGPT project folder> - <auto-generated title>.md`,
so the folder prefix (`Act uv`, `Cursor problems`, `AI RAG solutions`, …) is a topic hint and nothing more.

One file breaks the pattern: `Sep 26, 2025 12-17-17 PM Markdown Content.md` was saved by a browser
extension rather than exported, and is the only one whose name carries a real date.

## Dating method

Three independent signals, in descending strength:

1. **Web-citation dates inside the assistant turns.** ChatGPT's search results are stamped
   (`June 18 2025`, `2025-08-05`). The newest citation in a thread is a hard **lower bound**: the chat
   happened at or after it. Absence of citations is itself weak evidence of an early, pre-search-heavy chat.
2. **Repo cross-reference.** A thread naming a repo, path or artifact inherits that repo's git dates.
   `~/projects` first-commit dates: `hands-on-llm` 2025-06-19 (the first repo of the journey — nothing
   precedes it), `kri-local-rag` 2025-07-13, `dewpoint-app`/`dewpoint-ts` 2025-07-15,
   `arxiv-paper-curator` 2025-08-06, `docs-generator` 2025-08-27, `llm-eng-template` 2025-09-03,
   `stt-faster` 2025-10-05.
3. **OneNote overlap.** `sources/onenote/Onenote_AI_learning/` pages *do* carry real created/updated
   times, and several are pasted ChatGPT output. Load-bearing anchors:
   `My AI Learning Journey.md` created **2025-06-18 12:05 UTC** (holds the Phase-0 learning-path prompt,
   citations still carrying `utm_source=chatgpt.com`); `Wsl ollama` / `Windows ollama` / `New win ollama`
   **2025-07-01**; `Local llm server performance test` **2025-07-02**; `Win ooba` **2025-07-04**;
   `Learn_ AI Safety Research Eng` **2025-07-29**.

### The era boundaries this establishes

- **Chat-only era opens** just before **2025-06-19** (first `hands-on-llm` commit), with planning on
  **2025-06-18** and probably a few days of "should I even do this" before that.
- **Chat-only era closes ~2025-07-04.** The repo shows other tools arriving: 2025-07-02 first commit whose
  content mentions Copilot, **2025-07-04 `added gemini code review config file`**, 2025-07-05 VS Code
  settings + pre-commit with Gemini in the loop.

### Reproducing the citation scan

```bash
cd sources/chatgpt_conversations
grep -ohE "20[0-9]{2}-[01][0-9]-[0-3][0-9]|[A-Z][a-z]{2}[a-z]* [0-9]{1,2},? 2025" "<file>.md" \
  | sort -u | tail -5
```

Take the max, sanity-check it against a second-highest value (a single stray date is often a citation to an
old blog post, not a fresh search result).

## Known gaps and traps

- **A citation date is a lower bound, never the date.** A thread with no web search has none at all
  (that is 47 of the 74). A long thread's newest citation dates its *tail*, not its start.
- **Threads get resumed weeks later, so a single date is often wrong.** Worst offender:
  `AI RAG solutions - Recent Free Python Courses` opens as mid-June course-picking (the JetBrains/PyCharm
  toolchain mistake era) but carries 46 Copilot and 45 Cursor mentions further down. Anchor on the **first
  user turn**; treat the tail separately.
- **`Cursor problems - Cursor interpreter issue.md` and `... issue (1).md` are byte-identical duplicates**
  (116205 bytes each, `diff -q` reports no difference). Count them once — the real total is 73 threads.
- **Export order is lost.** The 74 files sort alphabetically by project folder, which correlates with topic,
  not with time.
- **Public repo.** These threads contain employer-identifying context and personal career material. Quote a
  *prompt shape* in `content/`, never a thread verbatim, and never the employer detail — the same rule the
  living spec already applies to private repos.

## The one thing that would replace all of this

The original ChatGPT export ZIP contains `conversations.json` with exact `create_time` and `update_time`
per thread. It is **not** on this machine (checked `sources/` and the home tree — only the rendered `.md`
files survived). Re-downloading the export and matching on thread title would replace every estimate above
with a fact, in one pass. Do that before citing any date here as measured.

Until then: every date on this page is an **estimate with its evidence attached**, and must be labelled as
such anywhere it reaches `content/`.
